# OnlyComment

Telegram-бот для группы обсуждений канала: удаляет сообщения, которые не являются ответами. Все разговоры остаются в комментариях под постами.

Переписан на Python и aiogram 3 по мотивам [glukki/telegram-replies-only-bot](https://github.com/glukki/telegram-replies-only-bot).

## Возможности

- Удаляет сообщения без ответа. Посты канала, служебные сообщения, сообщения админов и связанного канала не трогает.
- Два режима:
  - `any` — разрешён ответ на любое сообщение;
  - `thread` — разрешены только сообщения внутри веток комментариев к постам.
- Предупреждение автору с автоудалением (не чаще раза в 30 секунд на одного человека).
- Журнал удалений в отдельный чат или в личку.
- Настройки для каждого чата хранятся в SQLite и меняются в боте: через меню `/settings` или командами.
- Работает в режиме polling или webhook, выбор в `.env`.
- Бот работает только в чатах из `ALLOWED_CHAT_IDS`. Из любого другого чата он сразу выходит и сообщает об этом владельцам.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Заполните `.env`:

1. `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather).
2. `OWNER_IDS` — ваш user ID. Запустите бота, напишите ему в личку `/whereami`, впишите ID и перезапустите.
3. `ALLOWED_CHAT_IDS` — ID группы обсуждений. Проще всего добавить бота в группу: бот выйдет и пришлёт её ID владельцам. Владелец должен заранее написать боту `/start`.

Подключите группу:

1. Привяжите группу обсуждений к каналу (настройки канала → Обсуждение).
2. Добавьте бота в группу и сделайте админом с правом «Удаление сообщений».
3. Проверьте `/status` в личке с ботом: напротив чата должна стоять ✅.

## Запуск

```bash
python -m bot
```

Запускайте из корня проекта: `.env` и `data/` ищутся относительно текущей папки.

### Polling (`MODE=polling`)

Бот сам опрашивает Telegram. Подходит для любого компьютера или сервера, публичный адрес не нужен. Бот работает, пока запущен процесс.

### Webhook (`MODE=webhook`)

Telegram сам присылает обновления на `WEBHOOK_BASE_URL + WEBHOOK_PATH`. Нужен публичный HTTPS-адрес. Обычно перед ботом ставят nginx или Caddy с сертификатом, который проксирует запросы на `WEBAPP_HOST:WEBAPP_PORT`. Для локальной проверки подойдёт туннель `cloudflared tunnel --url http://localhost:8080` или `ngrok http 8080`.

- Запросы без правильного `X-Telegram-Bot-Api-Secret-Token` отклоняются с кодом 401.
- Если `WEBHOOK_SECRET` пустой, секрет генерируется заново при каждом запуске.
- `GET /health` возвращает `OK` — для мониторинга.

При переключении режимов ничего чистить не нужно: polling при старте снимает webhook, а webhook-режим ставит его заново.

## Настройка в боте

Настраивать чат могут владельцы из `OWNER_IDS` (любой чат из списка) и админы самого чата (только свой).

| Где | Команда | Что делает |
|---|---|---|
| личка | `/settings` | меню настроек ваших чатов |
| личка | `/whereami` | ваш user ID |
| личка | `/status` | состояние бота и права в чатах (владельцам) |
| группа | `/settings` | меню настроек этого чата |
| группа | `/on`, `/off` | включить или выключить модерацию |
| группа | `/mode any` / `/mode thread` | режим ответов |
| группа | `/warn on` / `off` / `15` | предупреждения; число — через сколько секунд их удалять |
| группа | `/logchat -100…` / `off` | куда присылать журнал удалений |
| группа | `/whereami` | ID чата |

Команды в группе от обычных участников не выполняются и модерируются как обычные сообщения.

## Ограничения

- Режим `thread` узнаёт ветки по постам, которые бот видел сам. Комментарии к постам, опубликованным до запуска бота, считаются ответами только тогда, когда отвечают прямо на пост.
- Если группа станет супергруппой, её ID сменится. Бот пришлёт владельцам новый ID, его нужно вписать в `.env`.
- Список админов кешируется на 5 минут. Новому админу, если он пишет команду, бот перепроверяет права через 30 секунд.

## Структура

```
bot/
  __main__.py      точка входа, выбор режима
  config.py        чтение и проверка .env
  app.py           сборка Bot и Dispatcher, команды в меню Telegram
  runners/         polling и webhook
  handlers/        membership → common → settings → moderation (порядок важен)
  services/        логика удаления, кеш чатов, права, предупреждения
  db/              SQLite: схема с миграциями и репозитории
  filters/, middlewares/, keyboards/, texts.py
tests/             логика, БД и прогон апдейтов через Dispatcher
```
